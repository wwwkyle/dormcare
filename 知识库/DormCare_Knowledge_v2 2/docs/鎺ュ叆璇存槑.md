# 我的知识库接入说明

## 我使用的运行方式

我使用Python 3.12或更高版本。向量模型在CPU本地运行，不需要API密钥。首次运行会下载约90MB模型；报修文本不需要上传给模型下载服务。

```bash
python -m venv .venv
source .venv/bin/activate
# Windows可使用 .venv\Scripts\activate
python -m pip install -r requirements.txt
python retriever.py "热水器不知道怎么用，有操作指南吗" --role student
python evaluate.py
```

我已建立`data/knowledge.sqlite`。修改`data/chunks.jsonl`后，我运行`python retriever.py --build`重新建立向量。模型缓存默认放在`.model_cache/`，也可由环境变量`DORMCARE_MODEL_CACHE`指定；换用不同模型时，我重建全部向量。

## 我安排的后端接入位置

我将检索放在会话校验之后、生成回答之前。工单、权限、固定工时和排班继续由现有业务接口处理。

```python
from dormcare_adapter import retrieve_context

# current_user由服务端会话确定，不接受请求体自报角色。
result = retrieve_context(student_description, user=current_user)
if result["status"] != "prototype_evidence":
    return result["message"]
evidence_json = result["context_json"]

```

我将这段代码作为接入位置示例，尚未改成现有`app.py`的完整路由补丁。实际接入仍需匹配函数参数与返回格式。我将回答规则放在`docs/接入提示词.txt`。

资料中的“我”指资料整理者。我要求助手引用时说明这是资料整理者的经历，不声称是助手自己或当前提问者的经历。

## 我使用的检索方法

我使用`BAAI/bge-small-zh-v1.5`生成512维向量，以SQLite保存元数据与float32向量，再由NumPy精确扫描。我同时保留中文双字／英文词BM25与向量检索，默认使用RRF混合，常数60，各取前10条后返回前3条。

我将0.52保留为原型相关度阈值，它不是概率或诊断置信度，也未经过独立校准。融合结果中最高语义分通过阈值，不保证每个片段都能支持回答。我参考[FastEmbed官方模型表](https://qdrant.tech/documentation/embeddings/fastembed/)，模型注册信息标注MIT。
